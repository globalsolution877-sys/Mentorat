# Déploiement sur LWS

1. Installer les dépendances sur un ordinateur de développement : `npm ci`. Copier `.env.example` vers `.env.local` et renseigner `VITE_SUPABASE_URL` et `VITE_SUPABASE_ANON_KEY` (clé publishable/anon uniquement). Ces valeurs sont intégrées au build public ; ne pas utiliser une clé secrète.
2. Exécuter `npm run test` puis `npm run build`. Le dossier `dist/` contient les fichiers statiques et le `.htaccess` nécessaire au retour vers `index.html` pour les routes React. Tester les routes profondes sur l'hébergement. Node.js n'est pas nécessaire sur LWS en production.
3. Dans LWS Panel, activer le certificat HTTPS puis transférer **le contenu de `dist/`**, y compris le fichier caché `.htaccess`, dans le répertoire web du domaine par SFTP ou gestionnaire de fichiers. Vérifier que `mod_rewrite` est actif. Adapter la règle HTTPS aux éventuels proxys LWS et éviter les boucles de redirection. Déploiement prévu à la racine du domaine ; un sous-répertoire nécessite une configuration de base Vite et routeur adaptée.
4. Dans Supabase Authentication > URL Configuration, remplacer la Site URL actuelle (`http://localhost:3000`) par le domaine HTTPS réel une fois disponible ; ajouter explicitement les URL de redirection `/connexion` et `/nouveau-mot-de-passe` pour les environnements autorisés. Configurer et tester un service SMTP adapté, la confirmation d'e-mail et les limites anti-abus. Ne pas présumer que `globalmentorat.com` est déjà actif.
5. Vérifier les politiques RLS avec plusieurs comptes, les permissions de chaque rôle, les formulaires, la réinitialisation et le fonctionnement mobile. Finaliser la sécurité, la politique de confidentialité et les modules manquants décrits dans le README avant toute mise en ligne publique.

Le build doit être refait après toute modification des variables Vite. La connexion Supabase nécessite un accès Internet depuis le navigateur de l'utilisateur. Les règles de sécurité ne doivent pas dépendre uniquement des routes React.
